## 1. Resumen ejecutivo del cambio

| Antes (PRD post 2026-05-25 iter 4) | Después (post change-signal 2026-05-26) |
|---|---|
| **Merma = modelo DUAL** (D-4): `factor_uso_interno` + `factor_error_operador`, configurables por categoría (tipo_papel + size_papel) en piezas, con override por tienda, default = 0 (C-9 entera, FR-080..085) | **Merma = factor ÚNICO global**: un solo % de la venta (~0.9% inicial, calibrable en piloto), **igual para todas las tiendas y todos los tipos de papel**. | Base del forecast: ventas históricas + factores de merma + saldo SIM | Base del forecast: **99% ventas, 1% lo demás**. *"Me tienen que llegar las ventas nada más."* El inventario NO es base del cálculo de demanda. |
| Inventario: snapshot SIM diario como input de saldo (modelo (C) Coexistencia) | El owner **NO forzará captura/baja de inventario** (*"es una fiesta complicada"*); basarse en inventario actual *"siempre nos deja torcidos"*. | Cadencia: motor semanal / tienda quincenal (C-O21) | Cadencia semanal **confirmada y preferida** (*"más controlado"*), pero con **hueco de datos**: hoy sólo hay ventas mensuales; se requiere obtener ventas semanales (Big Data / BigQuery) o derivarlas. |
| FR-061 estado "Excel capturado o ingresado" (ambiguo, finding high del Validate) | **RESUELTO**: el sistema **genera** el reporte; los coords trabajan en **pantalla**; el Excel es **output hacia compras, no input**. Sin transcripción manual. |
| OQ-120 (atribución residual entre uso interno vs error operador) abierta | **MOOT / cerrar N/A**: al colapsar a factor único no hay dos categorías entre las cuales atribuir. |
| Output: "compatible con SolicitusDeInsumosTodos.xlsx" | Reporte de necesidad de demanda con **dos layouts a elegir con coords** (por SKU→tiendas vs por proveedor→tienda) + **dashboard de validación** (proveedor, tienda, SKUs, últimos pedidos vs recibos). |

**Impacto neto:** esta ronda **simplifica drásticamente** el corazón del producto (forecast = ventas + factor de pérdida trivial) y posterga la complejidad de merma a una fase futura. Reduce el riesgo técnico (R-1, R-7, R-8) pero abre dependencias de datos nuevas (ventas semanales, extracción ALLOC/TFS desde RMS/BigQuery).
