# Change Signal — PRD insumos-odemas — 2026-05-24

Documento de entrada para sesión `bmad-prd update`. Se redacta tras ronda de Party Mode (John PM, Winston Architect, Murat TEA, Dr. Quinn Problem Solver) **+** comentarios directos del owner Jonathan.

> **Cómo leer este documento:** las decisiones del owner mandan y son inapelables. La crítica de Party Mode se conserva como contexto y para surfacear cascadas y trade-offs implícitos. Cada cambio especifica **acción concreta** sobre el PRD.

## 1. Resumen ejecutivo del cambio

El producto cambia de naturaleza:

| Antes (PRD draft 2026-05-22) | Después (post change-signal) |
|---|---|
| Plataforma multi-actor: Jefe + Coordinador + Comprador downstream | **Automatizador de la consolidación distrital del Coordinador** |
| Jefe captura conteo asistido + arma solicitud en sistema | Jefe **CERO interacción** con el sistema (sigue capturando en SIM como hoy) |
| SIM: integración R/W con saneamiento progresivo (modelo A) | **SIM: modelo (C) Coexistencia con lectura unidireccional** (snapshots) |
| TFS: el sistema sugiere, decide, registra y refleja en saldo | TFS: el sistema **solo registra histórico semanal** (no sugiere, no decide, no ejecuta) |
| Mermas: detección de anomalías desde conteo asistido + reconstrucción | Mermas: **histórico → merma esperada por tienda × mes**, configurable por coordinador, alimenta forecast como factor |
| Rotación de guardia: gobernada por el sistema | Rotación de guardia: **operativa fuera del sistema** (los coordinadores la organizan ellos) |
| Alertas mid-cycle disparadas por jefe (botón) | Canal de alertas del jefe: **fuera de scope** v1 (sigue informal) |

**Implicación de teoría del cambio (Dr. Quinn, validada implícitamente por owner):** v1 no ataca la causa raíz (divergencia físico-teórico en SIM). La asume como precondición. **Trade-off consciente:** scope manejable a cambio de no resolver el problema epistémico de fondo. Esto debe quedar declarado explícitamente en §11 Out-of-scope y §12 Riesgos en el PRD final, no enmascarado.
